# Module map

The app is already split by responsibility; it deliberately uses classic scripts and a `window.CM` namespace instead
of ES modules or a bundler, because the site must run from `file://` and be hostable as plain files. Think of each
directory as a module with an explicit public surface.

| Module | Where | Public surface |
| --- | --- | --- |
| Namespace/util | `js/core/ns.js` | `CM`, `CM.util` (`$`, `el`, `esc`, `qs`, `loadScripts`, …) |
| Settings | `js/core/settings.js` | `CM.settings` (board theme, animation/reduced motion, coordinates, sound) |
| Sound | `js/core/sound.js` | `CM.sound` (preload/play/stop, Lichess piano set) |
| **Rules/engine** | `js/engine/` | `CM.geometry`, `CM.movement`, `CM.Variant`/`CM.spec.buildVariant`, `CM.Search`, `CM.spec` |
| **Game controllers** | `js/game/spec-game.js`, `js/game/game-frame.js` | `CM.SpecGame`, `CM.GameFrame`; mode hooks call `ctx`/`host` |
| **Board view** | `js/ui/board-view.js` | `CM.BoardView`: render, input, keyboard, animation, marks |
| **UI chrome** | `js/ui/game-ui.js`, `js/ui/settings-panel.js` | `CM.gameUI` (clocks, move list, players, modals), `CM.settingsPanel` |
| Lobby | `js/lobby/lobby.js` | `CM.lobby` (video cards, search, categories) |
| Shell/routing | `js/app.js` | `CM.app`: bundle loading, hash routing, screen swaps, error messages |
| Bots | `js/bot/` | `CM.stockfish`, `CM.maia`, `CM.bot` |
| FX/3D | `js/fx/` | `CM.vfx`, `CM.scene3d` |
| Mode hooks | `js/modes/` | `CM.defineHooks(name, hooks)`; one file per mode |
| Canvas games | `js/games/` | `CM.defineGame(name, factory)` |
| Legacy library | `js/legacy/` | ported 8x8 engine/glue; shared top-level scope |
| Mode data | `data/modes/*.js` | `CM.mode(spec)`; generated by `tools/build-data.mjs` |

## Load order

`index.html` loads only the lobby path: data indexes, `ns`, `settings`, `sound`, `vfx`, `board-view`, `game-ui`,
`settings-panel`, `lobby`, `app`. `js/app.js` then loads bundles on demand:

- `game`: geometry → movement → variant → search → spec → events → bot engines → stockfish → maia → bot → scene3d →
  spec-game → game-frame.
- `legacy`: `data/legacy_modes.js` → `engine8` → `glue` → `modes_extra` (one shared scope; order matters).

The game bundle is prefetched when the lobby is idle, so opening the first mode is fast. A mode file is loaded as its
own `<script>` (or from the generated bundle on `file://`), then its hooks module, then the controller starts.

## Changing things safely

- **Rules:** change `js/engine/movement.js` / `variant.js`; run `npm test` and `npm run sweep`. Variant behavior is
  data-driven through piece definitions and `rules`, so avoid special-casing a video id in the engine.
- **Board/input:** `js/ui/board-view.js`. Keep the `render()` model contract; modes decorate squares through
  `model.squares[i].cls`/`html`. Keyboard input must go through the same `cb.onTap`/click path as the mouse.
- **Chrome:** `js/ui/game-ui.js` owns player bars, clocks, move list, captured pieces, overlays and toasts. Modes talk
  to it through the controller's `ctx`/`host`, not by reaching into the DOM.
- **Modes:** prefer a data spec (`setup`, `pieces`, `rules`, `bot`, `vfx`) over hooks. Hooks live in `js/modes/` and
  get `ctx` (state, legal moves, params, host) — see `docs/ARCHITECTURE.md`.
- **Generated data:** never hand-edit `data/videos.js`, `data/modes/index.js`, `data/legacy_index.js`,
  `data/modes.bundle.js` or `data/kinds.js`; run `node tools/build-data.mjs`.

## Unused code and assets

`qa/engine-sweep.mjs` catches modes that no longer build; `npm run validate` catches bad mode data and broken data
indexes. Dead-asset removal is not automated because mode art is referenced from mode files and generated indexes at
runtime. Before deleting an asset, search the whole repo for its filename (including `data/modes/`) and run the sweep;
if it is genuinely unused, delete it in its own commit so it is easy to restore.
